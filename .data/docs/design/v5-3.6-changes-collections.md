## §1.3 entries

1. **§2 Generations: `gen:u2` in every add, stored by the client** — accepted (§2, as a design-first decision). Added
   the client's row-acceptance rule, which the research left open: a held row applies on an add only when its `gen`
   matches *and* its frame tick is at least the add's tick, so an aliased `gen` (four occupants, at least 8 s apart)
   can never apply a stale row. R16's shared decoy slots also depend on it.
2. **§3 Cell chunks, copied up to 9 per viewer, hysteresis records as pieces** — accepted (§8.4). The grammar gains
   `kind:u1` on state chunks, separating column-codable rows (kind 0) from byte-aligned pieces (kind 1); the bit
   layout is the wire unit's.
3. **§3 Visibility classes encoded per class** — changed (§9). Every class field is coded `t.optional` of its codec,
   not only gated ones: an owner or team change has to send "hidden" to the viewer losing the class. Transitions go
   in the viewer's own chunk; chunk order within a frame makes a gate flip correct, and `changed` fires once per
   record per frame (§2).
4. **§4 Scoped events `:about`** — changed (§10). Now `Net.hit:field("target"):about(Net.fighters)` (core-api D1).
   Events only: a server request names its one player, so scoping it would only turn `invoke` into a new outcome.
   Holders are taken after the flush's adds and before its removes; with several scoped fields a viewer must hold
   every named record; a nil field scopes nothing.
5. **§4 Interest membership by cells, hysteresis, focus, look-ahead** — accepted (§8.3). Made exact: XZ cells, the
   finite-difference velocity over the ticks actually filed, `ReplicationFocus` as a `BasePart` or `Model` (pivot),
   then `Character.PrimaryPart` (members checked in the API dump 0.741.19); a viewer with no focus yet holds nothing.
6. **§4 Build-time PVS and per-pair predicate** — changed (§8.5). The PVS narrows per (viewer bake cell, interest
   cell), derived at the `interest` call, so cell chunks survive; this requires R to be a multiple of the bake's
   cell (decision below). Run-time raycasts per pair are not built; a game calls `Raycast` in its predicate.
7. **§7 Accumulators and a 40-bucket pass for interest collections** — changed (§7). One rule (largest accumulated
   weight first) with two implementations, the FIFO for constant weights and buckets for interest, merged by one
   selection step; the bucket index is defined; the 2 s age floor applies to every collection.
8. **§2 Decoy pool up to 256 of `maxRecords`** — changed (§2): superseded by R16. One allocator for records and
   decoys; `maxRecords` covers `MaxPlayers` × `maxPerViewer` decoy slots; counter `decoysUnplaced`.
9. **§5 Per-player variants keep downstream layouts per build** — accepted (§5).
10. **Woven `patch(key, {…})` turns `unknownPatchKey` into a build diagnostic** — changed: not specified here. It is
    a weave diagnostic (inferred by its source, unverified), so it goes to the tooling unit (Needs elsewhere).

## Lead decision: one callback rule

- **Every game callback Lync runs: a reused runner thread, three outcomes (returned, threw, yielded); on a yield,
  `task.cancel` on the thread, then the declared fallback** — accepted (§8.7). Draft text abandoned a yielded
  thread without closing it, so the engine could still resume it when its wait returned and run game code against
  stale state; `task.cancel` closes it so it never resumes (Roblox docs, per the `luau` skill's references; it
  errors only on the running thread or one that resumed another coroutine, and the runner is suspended when Lync
  cancels it). Fallbacks unchanged: `focus` keeps the last cell, `predicateOnError`, `weight` 1, `onError`.
  `task.cancel`'s cost is unmeasured (the CLI has no `task` library).

## Decisions made in this unit

- **D1 Row acceptance by `gen` and add tick** (§2): closes the aliasing case the generation fix leaves.
- **D2 `changed` fires once per record per frame** (§2), so a record touched by several units in a frame (classes,
  pieces) reaches game code once.
- **D3 State chunk `kind` bit and pieces chunk** (§3): pieces must be byte-copyable, rows inside a chunk aren't.
- **D4 One scheduling rule** (§7): age floor, then the class ⌊log2 s⌋, then age; FIFO (constant weights) and
  buckets (a `weight` function) are its two implementations; weights and the age floor are the developer's
  (review M9, scope G3).
- **D5 PVS at (viewer bake cell, interest cell)** (§8.5), keeping cell chunks; options were per-record pieces and
  per-bake-cell chunks.
- **D6 No focus, no members** (§8.3): "everywhere" would show every record to a client that never spawns.
- **D7 A new decoy must be inside the block** (§8.6): a real record never enters at ring distance.
- **D8 Class fields are all optional-coded** (§9); a throwing or yielding binding takes the developer's `onError`
  (review m4, scope G5).
- **D9 `:about` on events only; several fields intersect** (§10).
- **D10 The ack round-trip sample takes only each ack's newest seq** (§11.1), keeping the ack delay to one flush.
- **D11 Rendering clock**: τ* from the newest frame, 4% slew, one-flush dead band, snap at 0.25 s (§11.2).
- **D12 Cuts as a per-record segment bit** (§11.3).
- **D13 Reliable horizon H from the receipt** (§12.3): reliable fields at R, membership and D read at H.
- **D14 `Lync.perceived(player)` holds per-frame and per-player inputs only** (§12.5); P, the window and D are per
  collection, in each `rewound` result (review B3).

## Conflicts (§2)

- **2.1 #16 what verifies a claim.** Resolved as `v5-checks.md` §6.2 has it: a validator, or any check of any kind
  on the leaf or an enclosing record (§3.3).

  Challenge `after` is the integrity unit's.

  dropping messages (D2). Check policies are the checks unit's.

- **2.2 #5 same-bytes guarantee.** Resolved in §3.2: identical bytes at identity layouts; mixed paths decode only at

  each side already has its own `invoke` signature, and the client would pay a clock read and a `GetNetworkPing`
  per ask for fields no decision reads.

## Decisions made here

- **D1 Field handles** (§3.4). Every server declaration about one field goes through `Net.<def>:field(path)`, a
  handle typed by the field; options listing several fields take path strings typed as unions. Verified on both
  solvers and tsc (`field_handle`, `field_handle.ts`), and the runtime path's type function builds the same
  overloads (`field_handle_typefn`). Path overloads with option tables fail under the new solver
  (`overloads_options`).
- **D2 The claim requirement is enforced at handler declaration** (§3.3): `claimUnverified` becomes a caller error
  thrown by `connect`/`handle`; no message is dropped for it; counter `claimsUnverified` goes.
- **D3 A message with no handler** is dispatched to nobody and counted (`messagesUnheard`); an ask is answered
  `unanswered` at once (§3.5, §5.2).
- **D4 `round(data)`** on client views of client-sent events and requests: decode(encode(data)), nothing sent;
  `valueRefused` on refusal (§3.5).
- **D5 Interpreter form**: the interpreter as built; fixed-position closures save 29 µs/s at the busy model for a
  second encoder form (§2).
- **D6 `optionPlacement`**: one declaration error for an option the definition's kind, direction or lane doesn't
  take (§3.4); replaces `sealedPlacement` and closes the unspecified case of, say, `lane` on a request.
- **D7 Server result timing** is `number?` in the failure arm (§3.5).
- **D8 Results are not frozen**: one caller owns each; facts are frozen because observers share them (§3.5).
- **D9 The shared schema module replicates on both paths** (Q16, §3.5).
- **D10 Definition options live in §3.4's table**, `sealed.*` and `perceived` included; their mechanisms are
  specified in `v5-checks.md` and `v5-collections.md`.
- **D11 `visibilityPlacement`**, at most one visibility modifier per field (§3.3).

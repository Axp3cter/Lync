## §1.4 entries (`v5-tooling.md`)

### §1 Outputs
1. **Manifest gains `buildId`, `rotationSeed`, drawn c/d/pool index, per-definition closed/open, woven sites, weave
   hash, `foreignRemotes`, reachability and `dynamicAccess` sites, woven-copy digests, scanned-script inventory** —
   accepted (§1.2). The drawn values sit in one `rotation` object defined by reference to `v5-integrity.md` §2, so the
   manifest follows whatever that section draws; the weave hash is named `idTableHash` (see decision D5).
2. **No debug map; replay and inspector take layout from the release manifest** — accepted, written as a decision
   (§1.2), and the inspector's capture replay states it (§6).
3. **Shard line-1 SHA-256 self-digest over LF-normalised bytes; identity constants in the body; manifest keeps
   generator identity separately** — accepted (§1.1, §1.2: `generator.coreDigest` against a shard's `code`).
4. **`report.md` gains streaming settings, `refers` × `decoys` review list, `foreignRemotes` table** — accepted
   (§1.3), plus `remoteCreations`, the rotation costs and trap names.
5. **Generator invariants** — changed: exact limits (fewer than 32,768 closures, `kMaxClosureCount`, replacing
   "about 32,000"); the 200,000-character cap enforced by a derived 200,000-byte part split; the 1 M native IR

7. **Generated function names stay readable** — accepted (§1.1; R10 reason quoted).

### §2 `lync.toml`

## Simplifications (§3)

- **3.2 `weaveUnresolved` `reason` 1–5** — split into five codes, each with its own fix and severity key.
- **3.2 `editedShard` error under `check`, warning under `build`** — one fixed error; under `build` and `watch`
  nothing is overwritten while it holds. Options were: per-command severities (a merged mode), a warning everywhere
  (`lync check` would pass an edited shard), error everywhere (an edit is never lost silently; restoring or
  deleting the file clears it). Chosen: error everywhere.
- **3.2 `build.tagRounds` range cost** — the drawn c is recorded in the manifest's `rotation` and the report states
  the build's cost from it (§1.2, §1.3); the option itself is the integrity unit's.
- **3.3 `build.playerVariantScope` contents** — owned by `v5-integrity.md` §2; tooling states the woven-build
  restriction exactly (`"upstream"` with `lync weave` is `configRange`, §5.6).
- **3.3 Trap name rule** — defined (D4).
- **3.3 `unparsed` vs `weaveUnparsed`** — one code, `weaveUnparsed`.
- **3.3 "core hash" for two digests** — `generator.coreDigest` (generator identity) and a shard's `code` digest
  (drift) (§1.1, §1.2).
- **3.4 `weave.inlineMaxSites` 2, `weave.ids` "site", `check.weaveCoverage` "warn"** — 2 and "site" marked chosen
  with their inputs; `weaveCoverage` removed; the other weave defaults derived (§5.7).
- **3.4 `[[pvs]] cell` 32, `samples` 2** — marked chosen with measured costs (§2).
- **3.4 `freeFormField` threshold 2^16** — marked chosen with its inputs (§3.4).
- **3.4 `check.dynamicAccess`, `foreignRemotes`, `decoyRef`, `unscopedRef`, `freeFormField` all "warn"** — derived
  by one rule (§3.2): "error" when no known cause is correct code, "warn" when one is, "off" only for
  `foreignBindable`.
- **3.5 Wording** — "about 32,000 closures" → fewer than 32,768; "about +530 B", "about +50 B", "about 650 B" → mean
  per-site bytes from `codecs-in-scripts/size.out` (124, 177, 654 B); "about 3 µs", "expected to be cheaper",
  "smaller" (BC §1.6) → not carried (the design states measured totals only); "takes intent" (BC §3.3) → the trigger
  states the case ("regenerating … gives another digest"); "cheap in CI" (IR §4.2) → bake seconds stated;
  "within the noise" (CIS §9) → per-call medians stated.
- **3.5 `[variants] count = N` missing fields** — rejected with the key (2.1 #5).

## Cross-unit questions (§4)

  Studio's `GenerateGUID` marked public-quality until their entropy is verified (§4.1, §4.2, §8); `rotationSeed` only

  would remove the bait `:trap()` relies on and Studio's `staleShard` path.
- **#17 Per-player variant rule** — tooling side only: option names (2.1 #5) and the woven-build scope rule; the rule
  itself is the integrity and wire units'.

## Decisions made in this unit

- **D1 Instance-path notation** (§1): names joined by `.`, with `\.` and `\\` escapes, so paths with dots in names
  are unambiguous in the manifest, the site order and diagnostics.
- **D2 Shard parts** (§1.1): split at 200,000 bytes of source, derived from the reported `Source` cap.
- **D3 Fixed native rule** (§1.1): server parts `--!native`, client parts none, no option.
- **D4 Trap names** (§1.1): pieces of the namespace's own names, single and ordered pairs, drawn under `rotationSeed`;
  `trapNamesShort` when too few; `trapsIncomplete` for GM's unnamed "ignored (build diagnostic)" case.
- **D5 `idTableHash`** (§5.5): name chosen over `weaveHash` (misnames unwoven builds with traps) and `layoutHash`
  (collides with the runtime path's `layout` field and `layout.vary`).
- **D6 One code per trigger whose fix or setting differs** (§3.2), and the default-severity rule; one `check.<code>`
  key per configurable code.
- **D7 `--place` flag instead of `[check] place`** (§4.1).
- **D8 `--published` without the identity fallback** (§4.3).
- **D9 `[types] solver` removed; `check.solverOff` added**: the key's only effect was to silence `solverOff`, a second
  way to set that code's severity (principle 4).
- **D10 `rawRemote` scans packages too and adds `:InvokeClient(`**, skipping only Lync's own package by its runtime
  header, as `foreignRemote` does; `Packages/` code fires real remotes outside Lync.
- **D11 One token-level scan in every host** (§3.3): the parser-qualified callee rule is not used, since hosts would
  then write different server shards for one project.
- **D12 `project.sourcemap`** (§2): the file→instance input every container rule needs, required when such a check
  runs without `--place`.
- **D13 One manifest per build run**, rewritten by `lync weave` with `wovenDigest` and `wovenScripts`, instead of a
  second woven manifest; consumers take `--manifest`, default `output.manifest`.
- **D14 Studio-only manifest** in `ServerStorage.Lync.Manifest`; config in `ServerStorage.Lync.Config`.
- **D15 Weave gate's 200 value sets per site** (chosen, as the prototype); a gate failure is `internal`.
- **D16 Handler unpacking registers through a fields entry** and the delivery builds the table only when a
  table-form handler is also registered, so code outside the place keeps working (§5.8).
- **D17 SARIF**: "added if a user's CI consumes it" removed (a conditional deferral); not built, with its reason.

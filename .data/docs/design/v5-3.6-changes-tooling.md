## Decisions made in this unit

- **D1 Instance-path notation** (§1): names joined by `.`, with `\.` and `\\` escapes, so paths with dots in names
  are unambiguous in the manifest, the site order and diagnostics.
- **D2 Shard parts** (§1.1): split at 200,000 bytes of source, derived from the reported `Source` cap.
- **D3 Fixed native rule** (§1.1): server parts `--!native`, client parts none, no option.
- **D4 The generator emits only what the schema declares** (§1.1; replaces the first draft's generated trap names,
  `trapNamesShort` and `trapsIncomplete`): with the schema module replicating (core-api D9), any generated
  definition is the key-set difference between schema and shard; a trap is a schema definition the developer
  writes and marks `:trap()`, and Lync guarantees it is emitted like every other definition.
- **D5 `idTableHash`** (§5.5): name chosen over `weaveHash` (misnames a field every protocol-2 `HELLO` carries) and `layoutHash`
  (collides with the runtime path's `layout` field and `layout.vary`).
- **D6 One code per trigger whose fix or setting differs** (§3.2), and the default-severity rule; one `check.<code>`
  key per configurable code.
- **D7 `--place` flag instead of `[check] place`** (§4.1).
- **D8 `--published` without the identity fallback** (§4.3).
- **D9 `[types] solver` removed; `check.solverOff` added**: the key's only effect was to silence `solverOff`, a second
  way to set that code's severity (principle 4).
- **D10 `rawRemote` scans packages too and adds `:InvokeClient(`**, skipping only Lync's own package by its runtime
  header, as `foreignRemote` does; `Packages/` code fires real remotes outside Lync.
- **D11 One token-level scan in every host** (§3.3): the parser-qualified callee rule is not used, since hosts would
  then write different server shards for one project.
- **D12 `project.sourcemap`** (§2): the file→instance input every container rule needs, required when such a check
  runs without `--place`.
- **D13 One manifest per build run**, rewritten by `lync weave` with `wovenDigest` and `wovenScripts`, instead of a
  second woven manifest; consumers take `--manifest`, default `output.manifest`.
- **D14 Studio-only manifest** in `ServerStorage.Lync.Manifest`; config in `ServerStorage.Lync.Config`.
- **D15 Weave gate's 200 value sets per site** (chosen, as the prototype); a gate failure is `internal`.
- **D16 Handler unpacking registers through a fields entry** and the delivery builds the table only when a
  table-form handler is also registered, so code outside the place keeps working (§5.8).
- **D17 SARIF**: "added if a user's CI consumes it" removed (a conditional deferral); not built, with its reason.

### Blocking
- **B1 Regenerate-and-compare doesn't pin its inputs** — accepted. §1 lists every generation input; the manifest
  records `inputs` (SHA-256 of `lync.toml`, each schema module, the canonical `scan`) and `scan` itself; `regenerated`
  1 runs in `lync check` only, and only when the body `buildId`, every input and the generator equal the manifest's,
  else `regenerateSkipped` (fixed warning, evidence `input`); `lync build`, `lync watch` and the plugin run only
  `regenerated` 0; `lync weave` takes the recorded scan result instead of rescanning.
- **B2 Every woven release fails its own CI drift check** — accepted. `lync weave` rewrites line 1 of each part it
  changes and records `wovenDigest`; `regenerated` 1 compares a woven part with `wovenDigest`; a check over a woven
  place runs no scan; CI's check step now reads the unwoven `game.rbxl` before weaving.
- **B3 The weave gate can't pass under `"site"`** — accepted. Decode-equality per CIS §7.3 for site modes, byte
  equality only for `"generic"`; seed = canonical index + 1; the build's own `[build]` settings; identity
  permutation and permutation seed 1; §5.1 now says "deliver the same values".
- **B4 Generated traps are the key-set difference with the shipped schema** — changed (different fix). The schema
  module stays on clients (core-api D9), and trap names and placement are the developer's (author rule), so the
  generator emits only what the schema declares: a trap is a schema definition the developer writes and marks
  `:trap()`, emitted exactly like every other. The trap-name rule, `trapNamesShort`, `trapsIncomplete`, the trap
  set in `idTableHash` and the manifest's `traps` are removed; integrity text under Needs elsewhere.

# Draft 3.6 consistency phase: brief for every consistency unit

Seven architect units revised the design in parallel. Each wrote a change record, `design/v5-3.6-changes-<unit>.md`
(tooling, core-api, wire, runtime, integrity, collections, checks), and each record ends with one or more "Needs
elsewhere" sections: exact text other units' files must take. A naming review, `reviews/v5-3.6-naming.md`, sets one
convention and a rename table for every code, fact, counter, evidence field, option and API name. Each consistency
unit makes one piece of design text agree with all of that.

## What you do

1. Read `design/v5-3.6-architect-brief.md` (the rules), the naming review in full, and every change record's "Needs
   elsewhere" sections (all passes: first, second, third).
2. Collect every item addressed to your text. Apply each one, or reject it with a one-line reason grounded in a rule
   or in the text another unit already settled. Where two items conflict, apply the later decision and say which.
3. Apply the lead decisions recorded in `.data/docs/agents.md` under "Next" that touch your text (one callback rule;
   `callerProbe.splitFrames` removed; field handles from a `fields` table, `Net.<def>.fields.<name>` and
   `.fields["a.b"]`, replacing every `:field(...)`).
4. Apply the naming table's renames to every name in your text, including names your text cites from other files.
   Where the table splits a name, use the split it gives. Where your text uses a name the table doesn't cover, name it
   under the convention and list it.
5. Fix cross-references (section numbers, file names) that the revision moved.
6. Make no new design decisions beyond what an item, a lead decision or the naming table requires. If something can't
   be made consistent without one, list it under "Open" with the two texts that disagree.

## How to write

- **Edit only your own text, with targeted edits. Never rewrite a whole file:** another unit may be editing a
  different section of the same file at the same time.
- Record: `design/v5-3.6-consistency-<unit>.md`. Start with a checklist of items by source, tick each as you apply
  it, then list renames applied, names you named, references fixed, and "Open".
- If an edit fails, mark it "not done" and continue.
- Don't commit.
- Return only: the record's path, counts (items applied / rejected, renames, open), and the open items in one line
  each.

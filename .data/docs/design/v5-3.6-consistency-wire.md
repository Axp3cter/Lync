## Open

1. **`in`'s presence races the `WELCOME`.** `v5.md` §4.1 and `v5-collections.md` §15.5 make `in` present "on
   connections with a welcomed namespace that declares a stream", but a state frame is unreliable and can be decoded
   before the reliable frame carrying that `WELCOME`; server and client would then disagree on the header's length
   and the client refuses the frame. Needs a decision by the collections unit (for example, presence from a state the
   client has acknowledged, or a presence bit on every state frame at 1 bit each).
2. **Stream kind byte.** `v5-collections.md` §15.2 says "hash kind byte 4"; `v5.md` §4.7 has kind 4 = string table
   (fixed by S0) and now gives streams kind 5. Collections' §15.2 should read 5.
3. **`layoutMismatch` under `buildMismatch`.** The naming review's §11.2 rule gives a trigger its own code when its
   fix differs; the `path` 0 `HELLO` under `layout.vary` is fixed by the server's option or the client's path, not by
   deploying one build. Whether it becomes its own code is the runtime unit's (§7.3) or the naming critic's call.
4. **The client's native report of `MISMATCH`.** `MISMATCH` carries no fields, so the client can't tell
   `buildMismatch` from `helloNamespaceUnknown`; §4.6 now says only "the client reports it natively once (§7.2)". The
   code it uses is §7.2's (runtime).
5. **`REPORT` size in `v5-integrity.md` §4.** "8–17 B with the tag … 8–12 B for four counts of 0–60" disagrees with
   the probe (four counts at 60 is 13 B; the self-check case is 18 B). Integrity's text should cite §4.6's figures.
6. **Client decode allowance units.** The client still counts elements (2^22 per frame) while the server counts
   decode units; the value is now "chosen". Whether a client should count units too is the runtime unit's (§7.5).
7. **Strings counters.** `stringLiteralsCapped` is named here; the other strings counters in the wire unit's
   "Needs elsewhere" (`stringLiteralsHeld`, `stringEntriesFreed`, …) are §7.4's and not covered by the table.
8. **A stream's `data` and instances.** `v5-collections.md` §15.2 excludes strings, buffers, arrays, maps,
   optionals and unions from a stream's `data` but not `t.instance`, while §4.1's stream chunk has no `instances`
   field. Either §15.2 excludes `t.instance` too or the chunk gains the field; collections' call.

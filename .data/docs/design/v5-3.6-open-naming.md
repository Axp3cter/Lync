## Decisions on the open items

**D1. `pvs.raysPerAxis` → `pvs.samplesPerAxis` (renamed).** The option counts sample points per axis per cell
(`v5-tooling.md` §2's unit column); rays per cell pair are its fourth power, so "rays" named the derived quantity.
C5: a count is a plural noun of what it counts.

**D2. `check.freeFormCodes` → `check.minFreeFormCodes` (renamed).** It is a threshold that a leaf's code count must
exceed for the lint to fire, and C5 names thresholds `min<Quantity>`. The strict "more than" stays, as for
`clock.minSlope`, which the slope must exceed (`v5-integrity.md` §6); range and default unchanged.

**D3. `layoutMismatch` leaves `buildMismatch` (split).** §11.2's rule gives a trigger its own code when its fix
differs. `buildMismatch` is fixed by deploying one build. A `path` 0 `HELLO` meeting `layout.vary` is fixed by the
server's option or the client's path. The evidence flag becomes the fact `layoutMismatch` (C2: the layout's two
values differ), with no evidence. The runtime text already has the row.

**D4. The client's native report of any `MISMATCH` is `mismatchReceived` (renamed from `schemaMismatch`).** `MISMATCH`
has no fields, so the client can't tell `buildMismatch`, `layoutMismatch` and `helloNamespaceUnknown` apart. Its
code names what it observed: a `MISMATCH` arrived (C3 `Received`). The subject is the wire message type, written
lowerCamel (C1). The runtime text already uses it.

**D5. Telemetry type `Stream` → `RingCopy`; "streams" in telemetry prose → "rings" (renamed).** Since
`v5-collections.md` §15, `stream` is a definition kind. `Lync.telemetry.read` returns a copy of one ring, the word
§8.2 already uses for the storage. The section is now "Rings and their entries"; the PVS-unrelated "xorshift
streams" of `v5-integrity.md` §2.2 (a random-number stream, no API name) stay.

**D6. Telemetry fields.** `ms` → `clockMilliseconds`, `key` → `frameKey`, `n` → `count`, `dt` → `sinceTriggerSeconds`
(renamed); `flags` kept.
- `ms` is an `os.clock()` reading in a u32 that needs integer milliseconds for exact differences. C5 has no rule for
  it: durations are seconds and `arrivalClock` is in seconds. **Amendment to C5:** an `os.clock()` reading in
  milliseconds is `clockMilliseconds`, the one millisecond name, never a duration. The same name is used for the
  entry, the atom header and the copy's anchor, each defined at its moment.
- `key` alone is also a collection key; this is the frame key of `v5-checks.md` §3.1.
- `n` is the atom's entry count: `count`, as `AtomBatch.count` and `Fact.count` (n stays the math symbol).
- `dt` is a signed time relative to the trigger in seconds: C5's `since<Event>Seconds`, negative before it.
- `flags` is a noun for a bit set (C4); each bit is defined by its condition.

**D7. `stringTableFieldMissing` kept.** A table needs at least one marked field and has none: C3 `Missing`
("something required is absent when it is needed") fits. Only the rejected `Unused` was outside C3.

**D8. `callOptionMismatch` kept.** A later `layout.vary` must equal the value read at the first `WELCOME` and
differs: C3 `Mismatch`, with the option as the subject. It sits beside the `callOption…` set, as C-1 asks.

**D9. `"tickOutOfRange"` → split `"tickOutOfRange"` and `"ackMissing"`.** "P or R older than the ring" is an
interval (`OutOfRange`). A frame with no ack and none held (`ackSeq` −1) has no tick at all. Its subject (the ack)
and its cause differ: a player who has received no state frame yet, against ping above the window. So by §11.2 it is
its own outcome, `ackMissing`, in the form of the sibling `recordMissing`.

**D10. Strings counters.** Kept: `stringLiteralsCapped` (wire's name; the page defines the cap), `stringEntriesFreed`,
`stringReferencesReceived`. Renamed: `stringEntries` and the client's `stringEntriesHeld` → `stringTableEntries` (one
level, on each side, the same quantity), `stringBytes` → `stringTableBytes` (C4 level `<subject><Quantity>`, the
subject being the table), `stringDefinitions` → `stringDefinitionsSent` (a count takes a participle),
`stringLiteralsHeld` → `joinHoldLiteralsEncoded` (C-13: the join hold is always `joinHold…`; "held" alone is
rewind's sense). These match what `v5.md` §7.4 now has.

**D11. `streamBytesExceeded` kept.** It is the name in `v5-collections.md` §14, `v5.md` §3.4 and now §4.7. No
`streamChunkBytesExceeded` is left anywhere, so no edit was needed.

**D12. A check function's throw or yield counts in `checkFunctionsRaised`, `checkFunctionsYielded` (split from
`validatorsRaised`/`…Yielded`).** S-6 split the codes by subject so that a filter on validators doesn't catch
check functions. Counters follow their codes, so they split by subject too. `v5-checks.md` §1.7 and §10 are edited;
`v5.md` §6.1 and §7.4 already have them.

**D13. The server join hold's drop is `joinHoldBytesExceeded` (kept, one code on both sides).** It has the same
subject (a join hold's 32,768 B cap) and the same fix (send less to or from a namespace before its `WELCOME`). The
side is the observer, as for `joinHoldBytes`. The runtime text already says so; `v5-checks.md` §9.5 matches.

**D14. A PVS table that breaks its format → `callOptionMalformed` (split from `callOptionOutOfRange`).** The rules
broken are a format's grammar (base64 padding, length, header fields), which is C3 `Malformed`. `OutOfRange` is "a
number outside its declared interval". `callOptionOutOfRange` keeps `radius` not being a multiple of `cellSize`,
since `radius` is a number. **Amendment to C3:** `Malformed`'s message column gains the caller phrase
`must be <format>, got <first rule broken>`; it was written "(facts and build only)" for the uses it then had.

**D15 (found while checking N6). `inbound.elements` → `inbound.decodeUnits`, `inboundElementsExceeded` →
`inboundDecodeUnitsExceeded`, `joinHoldElementsExceeded` → `joinHoldDecodeUnitsExceeded` (renamed).** Draft 3.6
moved the bucket and the hold's second cap to decode units (`v5.md` §4.8, §7.5: "counts decode units, not
elements"). C3's `Exceeded` row says the subject names the quantity, so these names now state a quantity they don't
count. "Units" alone doesn't say which unit; the decode unit is the defined one. `messageElementsExceeded` keeps
its name: W is an element count.

**N1. core-api.** Kept: `internMisplaced`, `internTableUnknown`, `validatorDuplicate`, `limit.slackSeconds`,

"self-check" (`clientSelfCheckMismatch`, `selfCheckMismatches`, `selfCheckItem`, `selfCheckCase`, the manifest's
`selfCheckItems`), and C6 asks for a verb phrase for `true`.

**N3. integrity.** Kept: `clientOuterFrameMissing`, `canaryFormatRaised`, `canaryFormatYielded`, `keyCodecMismatch`
for `refers`, `gameKind`. Renamed:
- `canaryValueRefused` → `canaryFormatResultRefused`. Collections named the same trigger shape (a game function's
  return breaking Lync's rule) `weightResultRefused`; one form, `<function role>ResultRefused`, as faults are
  `<function role>Raised`.
- `decoyBehaviourRaised`, `decoyBehaviourYielded` → `decoyBehaviorRaised`, `decoyBehaviorYielded`, and the parameter
  `behaviour` → `behavior` in `decoys(behavior, …)` and `behavior(viewer, tick)`. Roblox's identifiers are American
  (`StreamOutBehavior`, `SignalBehavior`, both in this design), and a developer types the code as a string.
  **Amendment to C1:** identifiers use Roblox's spelling; prose keeps its own. No other British identifier exists in
  the five files (searched).

**N4. collections.** Kept: `focusRaised`, `weightRaised`, `weightResultRefused`, `inputCopyMismatch`, `fieldIndex`,
`inputsDiscarded`, `inputCopiesParsed`, `state.maxPendingSeconds`, `interpolation.jitterFraction`,
`ackRoundTripSeconds`, `rewindDelaySeconds`, `onError`, `predicateOnError`, `acked`, `inputsSkipped`. Renamed:
- `about`'s key-codec refusal, `fieldCodecUnsupported` → `keyCodecMismatch`. `v5.md` §3.4's one code set gives
  `keyCodecMismatch` to "a key codec unequal … to the one it must equal". `about` is `refers`' server-sent twin, and
  `refers` raises `keyCodecMismatch` for the same comparison.
- stream option `depth` → `depthTicks`. C5 makes a count a plural noun. Every other duration-like option in the
  design is in seconds, so a bare `depth = 2` reads as seconds. The wire field of `DEPTH` keeps `depth` (wire grammar
  keeps its names).

**N5. checks.** Kept: `DirectionField<D>`, and the prose "aim series", "a sender" (D5 extends this to the type).

**N6. tooling.** Kept: `check.minStagedNameBytes`, `column`, `raisedText`, `worstCaseBytes`, `variants`,
`selfCheckItems`, `callerSources` with `origin`, and the PVS fields `cellSize`, `originX`, `originZ`, `columns`, `rows`.
Renamed: manifest `maxMessageUnits` (U_max) → `worstCaseDecodeUnits`, `maxUnreliableInstances` (N_u) →
`worstCaseUnreliableInstances`. Both are computed worst cases, as `worstCaseBytes` is. C5 reserves `max…` for limits,
and U_max is in decode units (D15).

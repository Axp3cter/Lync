## Decisions and confirmations

**1. How an option names a field.**
- *Problem.* `v5.md` §3.4 introduced handles because declarations *on* a field have option types that depend on
  the field's type (`derive`'s `fn` returns it), and only a key read keeps those exact on both solvers. Some
  declarations of a whole definition also name fields in their options: `interest`'s `position` (one),
  `atom`'s and `rewind`'s `fields` (several). The rule said handles were the only way to name *one* field, which
  `position` broke.
- *Options.* (a) `position` takes a handle (`position = Net.fighters.fields.position`): one form for single fields,
  but a handle's type comes from its codec, not from its definition or depth, so another definition's handle or a
  nested `t.vector3` passes the type check and fails only at run time; and options would still have two forms
  (handle for one field, strings for several). (b) Every option that names fields takes path strings, one or
  several, typed as the union of the paths it accepts; declarations on a field stay methods of its handle.
- *Choice: (b).* The split is by role, not by count: a handle is always the receiver of a declaration on a field,
  a path string is always an option value. The union type checks definition, depth and codec at once. Checked: a
  concrete union (generated path) and a type function's union over a schema (runtime path) both accept correct
  literals and reject a misspelled one and one of another codec, under the new solver
  (`probes/open-semantics-3.6/position_path.luau`, `.out`: exactly the 4 expected errors, luau-lsp 1.70.1). Untyped,
  `fieldPathUnknown` and `fieldCodecUnsupported` at the call, as `v5-collections.md` §8.2 and §14 already state.

**2. Presence bit.** `v5.md` §3.3's modifier row now reads "one presence bit per class field per add or update
carrying it", word for word `v5-collections.md` §9's cost line; nothing to change.

**3. `REPORT` sizes.** By §4.6's formula (19 bits + 2⌊log2(c + 1)⌋ + 1 bits per field value, rounded up, + 4 B tag)
and the probe's SIZES line (rerun on Luau 0.740: output identical to `golden_wire.out`): 8 B one count of 1, 13 B
four counts at 60, 14 B five, 18 B six counts at 60 with `selfCheckItem` 202 and `selfCheckCase` 3. "8–17 B" was
wrong at its top and implied a bound that doesn't exist (`probes` grows between reports: 43 bits after 10 h). §5's
"3 B of fields beyond the others" is now the exact 20 bits for that case (23 bits against 3 for zeros).

**4. `report` bits in `WELCOME`.** `v5.md` §4.6's `WELCOME` row carries `report.checkListenerCaller` u1 and
`report.checkOwnTables` u1 in the connection's first `WELCOME`, between `callerProbe.maxProbesPerSecond` and
`clock.beaconSeconds`, as golden frame G10 encodes (both 0 there). `v5-integrity.md` said "1 bit in `WELCOME`"; its
option rows for these two, for the two `callerProbe` options and for `clock.beaconSeconds` now say "in the
connection's first `WELCOME`" with the width. No frame changes, so no golden vector changes.

**5. A `pvs` value that breaks the table format.**
- *Problem.* `v5-tooling.md` §2 fixes the bytes exactly; `interest` must refuse anything else at the call, by
  exact rules, and `EncodingService:Base64Decode` (takes and returns a `buffer`, API dump 0.741.19) has no
  documented behaviour on input that is not base64 (unverified), so a decode of bad text could yield bytes that pass.
- *Options.* (a) `callOptionOutOfRange`, its message naming the first rule broken; (b) a code of its own
  (`pvsTableMalformed`).
- *Choice: (a).* Naming §11.2 gives a trigger its own code when its subject or fix differs; here the subject is one
  call option and the fix is to pass a value inside that option's range, the same as for `radius`. A value of
  another Luau type is `callOptionWrongType`. The string is checked as padded standard base64 before decoding, so the
  decoder's handling of other input never matters. Order: base64 form; fewer than 14 bytes; `cellSize` outside 8–256;
  `originX`/`originZ` not a multiple of `cellSize`; `columns` or `rows` 0, or N > 65,536; length ≠ 14 + ⌈N²/8⌉; a bit
  past N² set. Cost: one pattern match and these reads, once at the call.

**7. Role markers in streams.** While this unit worked, `v5-checks.md` §7.1 changed to allow markers in "`data` of
`from = "client"` events and requests and of streams (`Lync.stream`)", matching `v5.md` §3.3's row, and
`v5-collections.md` §15.4 no longer mentions the claim requirement. Nothing left to reconcile; my own edit of the same
line was not made.

**8. The lint on streams.** Markers are allowed in a stream's `data` (`v5.md` §3.3, `v5-checks.md` §7.1), so the
lint that makes them protect must walk it too: `v5-tooling.md` §3.4's `freeFormRoleMissing` scope now reads "`data`
of `from = "client"` events and requests and of streams". Stream `data` has only fixed-width leaves, so of the lint's
codecs only floats and wide `t.int(min, max)`/`t.number`/`t.vector3` can fire there. Consequence kept consistent:
`refersMissing` walks "as `freeFormRoleMissing` walks it", but `refers` takes events and requests only (`v5.md` §3.4's
table), so its scope now excludes streams' payloads; otherwise it would ask for a declaration that throws
`declarationMisplaced`.

**9. `rewind`'s exclusion list.**
- *Problem.* §12.2 refuses a `fields` entry "whose codec has no fixed single-row width" and lists only strings,
  buffers, arrays, maps, optionals and unions; the ring holds each field's single-row code in a fixed slot, so the
  rule, not the list, is what's built, and a list that names part of it reads as permitting the rest.
- *Options.* (a) leave the short list (the rule already excludes the others); (b) complete it to the set
  `v5.md` §3.3's `:newest()` row and §15.2 name: add `t.int()`, Roblox enums, instances and custom codecs.
- *Choice: (b).* Each of the four has a variable width in `v5.md` §3.3 (EG-coded, EG-coded, an index of
  ⌈log2 c⌉ bits into one frame's list, `maxBits`-bounded), so the rule excludes them already; the list now states
  the rule's whole extension, as the two sibling rules do. Instances have the further reason streams have: a
  slot would hold a position in a frame's instance list, not an instance. No behaviour changes: the default
  (`:newest()` fields) is fixed-width by `newestCodecUnsupported`. The option row now says the paths are typed as
  the union of the fields `fields` accepts (`v5.md` §3.4, item 1), not of every field.

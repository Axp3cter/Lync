## Decisions

**1. When `in` is present.** *Problem:* the state-frame header has no length, so both ends must agree on `in`'s
presence before reading it; an unreliable state frame can be decoded before the reliable `WELCOME` that made a stream
namespace live, so "present with a welcomed stream namespace" gives two header lengths and the client refuses the
frame. *Options:* (a) on every state frame, `'0'` until a stream index was received (1 bit when empty); (b) a presence
bit in the first `WELCOME` from the server's loaded schema (0 bits per frame, but a namespace loaded later on the
runtime path gets no ack, and G10 changes); (c) presence from the acknowledged `WELCOME` receipt, which still needs a
per-frame signal, i.e. (a) plus a rule. *Choice: (a):* exact on both paths with no connection state; cost 1 bit per
state frame, 1 B exactly when the bits before the first chunk would end on a byte boundary: at most 20 / 60 B/s at
20 / 60 Hz with one state frame a tick (0.13–0.38% of `state.budget`'s default), and only on state frames.

**2. Instances in a stream's `data`.** *Problem:* `data` doesn't exclude `t.instance` but the stream chunk has no
`instances` field. *Options:* (a) refuse under the existing `streamCodecUnsupported`; (b) add `instances` to the
stream chunk. *Choice: (a):* an instance's code is u(⌈log2 c⌉), an index into one frame's list (`v5.md` §4.2), so it
has no fixed width, and `same`, `ref` against an index acked frames ago, and the redundant-copy comparison behind
`inputCopyMismatch` would compare positions in two frames' lists, not instances; (b) would need comparison by
referent and a list per frame. The exclusion list now also names `t.int()`, Roblox enums and custom codecs, which
the rule "fixed single-row width" already excluded (EG-coded, EG-coded, `maxBits` bounded; `v5.md` §3.3).

**3. Kind byte.** Not a choice: `v5.md` §4.7 gives streams 5, kind 4 is the string table, fixed by S0;
`v5-collections.md` §15.2 now reads 5.

**4. Why redundant copies aren't charged.** *Problem:* §15.7's reason cited 411 elements a second, the retired
per-schema element default. *Options:* re-derive in decode units, or drop the figure. *Choice: re-derive:* a copy at
its index's weight is p(6) = 2,798 ns, 28 units (`v5.md` §7.5), 43–98× its measured 28.5–64.7 ns parse; an
unmodified 60 Hz `move6` stream's 167–406 copies a second would cost 4,676–11,368 units, 6,356–13,048 with the 60
new indices, against the 10,000 provisional default `[acked-inputs §6.1, §7.1]`. The ratio holds whatever the
default becomes; the refusal figure moves with it.

**5. One code name.** *Options:* `streamBytesExceeded`, `streamChunkBytesExceeded`. *Choice: `streamBytesExceeded`:*
`reviews/v5-3.6-naming.md` §1.2's `Exceeded` rule names the quantity's owner and unit, as `messageBytesExceeded`
does for a message's worst case; the 960 B is summed over a namespace's streams, not one chunk, so "chunk" would
name the wrong subject. The wire consistency unit had already changed §4.7 to it; no edit was needed.

**6. Role markers in stream data.** *Problem:* `v5.md` §3.3 allows markers in a stream's `data`, `v5-checks.md` §7.1
didn't, and the research ran the claim requirement among steps 5–7 per index. *Options:* refuse markers on streams
(`roleMarkerMisplaced`), or allow them with the requirement at `connect`. *Choice: allow* `[acked-inputs §7.2]`: a
stream is a client-sent payload whose leaves can be claims (a reported position), checks and validators already run
on streams per index, and the requirement is not a step (`v5.md` §6.1): it runs once, at the stream's `connect`.

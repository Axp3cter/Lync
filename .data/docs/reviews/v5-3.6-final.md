### N1. Three codes registered as callers are reported natively — major

- **Case.** `v5.md` §7.1 registers `valueRefused`, `decoyKeyDuplicate` and `decoyMisplaced` in the `caller` family,
  and states "A family fixes a code's primary channel (§7.2)"; §7.2's caller row is "throw at the caller". But:
  `v5.md` §5.2: a `handle` reply its codec refuses is "reported natively as `valueRefused` at the definition";
  `v5-integrity.md` §8: a decoy record a codec refuses is `valueRefused`, a decoy key equal to a live record's is
  `decoyKeyDuplicate`, "each failure reported natively"; `v5-collections.md` §8.6 and §14: `decoyMisplaced` is
  "caller, reported natively (the behaviour's channel)". §7.2's own row for "decoy behaviour … refused result" says
  native report. So one code (`valueRefused`) has two channels, and two codes have a family whose channel they never
  use.
- **Why it matters.** The code unions and the registry pages are generated from the family (§7.1); a registry test
  that checks "family fixes the channel" fails, or passes by being wrong; a game filtering native reports by family
  misses these.
- **Fix.** `v5.md` §7.1: move `decoyKeyDuplicate` and `decoyMisplaced` from the milestone 3–7 callers to the faults
  (`v5-collections.md` §14's row: family `fault`). Give the two native uses of `valueRefused` their own fault codes in
  the form open-naming N3 set (`<function role>ResultRefused`, as `weightResultRefused`): `v5.md` §5.2 "reported
  natively as `handleResultRefused` at the definition"; `v5-integrity.md` §8 first bullet "a record a codec refuses,
  `decoyBehaviorResultRefused`"; register both in §7.1's faults. `valueRefused` stays the caller code of `fire`,
  `asDecoded`, `set`/`patch` and woven literal sites.

### N2. `canary.varyPerViewer` has two defaults — major

- **Case.** `v5.md` §4.2: "with `canary.varyPerViewer`, on by default, … so by default frames holding canary adds do
  [leave `FireAllClients`]". `v5-integrity.md` §9's option row: default `false` (derived: "which of the two matters is
  the game's"), and §12 lists "the `canary.varyPerViewer` default" as pending on that basis.
- **Why it matters.** It decides whether every canary add leaves `FireAllClients` and whether `canaryReceived` can
  name another viewer (`sentToSender` 0); an implementer reading the core ships the opposite of the option's home.
- **Fix.** `v5.md` §7.5 says these options are specified "in the file of the part they belong to, and nowhere else",
  so `v5-integrity.md` §9 wins. `v5.md` §4.2: "with `canary.varyPerViewer` (`v5-integrity.md` §9, off by default),
  the chunk is encoded once and each viewer's copy has 4 tail bytes rewritten …; a frame holding such a copy, or a
  decoy viewer's re-encoded chunk (§8 there), leaves `FireAllClients` for that flush."

## 2(a). A reliable claim event with a check, on the generated path

### Setup, and the first gap

The §3.4 game has no reliable client event with a claim field: `chat` is reliable with an `:input()` leaf, and
`strike`, the only claim event, is `lane = "unreliable"` (`v5.md` §3.4). The checks file's examples check a field the
core game doesn't have (`Net.strike.fields.origin:within`, `v5-checks.md` §1.2, §2.1, §7.3, whose §7.3 schema adds
`origin` to `strike`; `v5.md` §3.4's "a check on `strike.origin`"). That is finding A5. The trace uses the smallest
change that gives the requested case, **strike′**: `strike` with `lane` omitted (so reliable), and on the server

```luau
Net.strike.fields.target:derive({ fn = function(player, s) return Targeting.pick(s.aim) end, tolerance = 0, policy = "drop" })
Net.strike.fields.target:refers(Net.fighters)
Net.strike:connect(onStrike)
```

Build: `build.rotationSeed = "release"`, `build.playerVariantCount = 16`, `weave.ids = "site"`, every other key at
its default. The client site is `Net.strike:fire({ target = shot.target, aim = shot.aim })`: §3.5's `fire(shot)`
can't be woven, since "a resolved site of a record definition whose argument is not a table constructor" is
`weaveArgumentUnsupported` (`v5-tooling.md` §3.4).

### a1. Schema declaration

- **Codecs** (`v5.md` §3.3): `t.int(1, 2 ^ 40)` is "u(⌈log2(max − min + 1)⌉) of v − min": u40, n = 2^40;
  `t.direction(11)` is "octahedral, two u(bits)": two u11, n = 2048 each. `:claim()` "the leaf's role … Wire 0 B".
- **Order** (§3.1): "record fields … are ordered by name": `aim`, `target`.
- **Hash** (§4.7): kind u8 1, `from` 1, lane 1 (reliable now); `data` a record (type 23), `target` hashed as "26 role
  (u8: … 2 `:claim()`; then the codec)". Changing the lane changes the hash, not `buildId`.
- **Static bounds** (§3.4, §4.8): W = 1 + E(record) = 1 element; worst case 62 bits, far under 16,000 B.
- **Decode units** (§7.5): "w = ⌈p(L) / 100 ns⌉ … p(L) = p_0 + p_1 × L … each scalar leaf 1 … `t.direction` 2": L = 3,
  p = 2,399 ns, **w = 24 units**. The namespace's U_max is 24 (`buy`'s ask and `chat` are L = 1, 22 units), so the
  unit burst is max(48, 81,920) = 81,920 and the client hold's H = max(24, 40,960) = 40,960.
- **Lint** (`v5-tooling.md` §3.4 `freeFormRoleMissing`): `target` has 2^40 codes, more than
  `check.minFreeFormCodes` (65,536), and would warn; its `:claim()` silences it. `t.direction` is not on the list.
- **Gap.** A9: §3.4 says "Every value in the schema goes into the schema hash (§4.7)", but `limit.slackSeconds`, a
  §3.4 definition option, is not in §4.7's option list, and G6 has no slot for it (decoded by hand: after the codec,
  eight `00` for `reply` … `reliablePerSecond`, then `01 00` `ackEveryFrame`, `00` `sealed`, `00` `acked`).

  as x mod n from a 32-bit x, so `target`'s offset ranges over 2^32 of its 2^40 codes; exact, as stated.)
- **Shards** (`v5-tooling.md` §1.1): line 1 `-- Lync 5.0.0 | arena | client | part 1/1 | build … | schema … | code …`;
  identity constants in the body; server part `--!native`; the client shard holds the self-check items.
- **Variants** (`v5-tooling.md` §1.1, `v5-integrity.md` §2.4): 16 modules `ServerStorage.LyncVariants.<v>`, m_v the

### a3. Join: `HELLO`, `WELCOME`, variant binding, join hold

- **Server first** (`v5-integrity.md` §2.4): at `PlayerAdded`, assign v "uniform … among the variants no present
  player holds", clone `Value` into a `ScreenGui` named `Lync` under `PlayerGui`, and "answer that player's first

- **`HELLO`** (`v5.md` §4.6): version 1, `buildId`, schema hash (two u32), `idTableHash` (nonzero: woven), `path` 0,
  name `arena` (u7 length, bytes in the tail). It is untagged: "a reliable frame is untagged exactly when no
  `WELCOME` has been sent or its extended `rcv` is below F_w" (§4.5).
- **Server** (§6.1 step 5, §4.6): version, `buildId` (against its own and the connection's first accepted `HELLO`),
  schema hash and `idTableHash` equal; `path` 0 against a generated server is no `layoutMismatch` ("A generated server
  always sends 0", §3.2). It sends the connection's first `WELCOME`. G10's layout, recomputed by `wire.py` from §4.6's
  field list, matches byte for byte (index EG0, `layout` u1, epoch f64 low then high, `stateRate` u6, `delay` u8,
  key nonce, `tag.coverBytes` u15, permutation nonce u32, `callsPerProbe` u8, `maxProbesPerSecond` u6, two
  `report` bits, `clock.beaconSeconds` u4).
- **Client on `WELCOME`** (§4.5, §4.6): key = HalfSipHash-2-4/64 under S over (key nonce ‖ `01`); space keys K under S
  over (permutation nonce ‖ `02` ‖ schema hash low ‖ space); `layout` 0 keeps the shard's own layout; D₀ =
  ⌈max(2/`stateRate`, `minDelaySeconds`)/4 ms⌉ = 25 at 20 Hz.
- **Variant binding** (`v5-integrity.md` §2.4): a thread waits for the marked `ScreenGui`, requires `Value`, installs
  m_v. "A client holding no mask yet tags nothing; its tagged frames wait" (`v5.md` §4.5).
- **Join hold** (§5.3): `strike′` fired before release is "encoded at fire as a run of its own" and charged
  ⌈bits/8⌉ (summed, rounded up) and 24 units, caps 32,768 B and 40,960 units; released "once a namespace's `WELCOME`
  has arrived and, with variants, the mask is installed".
- **Gaps.** A1 (major): a namespace whose first use falls between the first `WELCOME` and the mask. A2 (major): what
  "encoded at fire" can contain before the `WELCOME`.

### a4. Encode

- **Frame** (`v5.md` §4.1): `header (up, reliable) := caller:u1 ack rcv:u8`; `toc (up, both) := segs(run)`; `run chunk
  := id:u(w) count−1:EG0 [instances:EG0] rows`; upstream chunks unaligned; then `align`, the tail (none here) and
  `tag:u32le`.
- **Row** (§4.3, `v5-integrity.md` §2.2): fields in the build's order; each bounded code q "travels as w = (q + c) mod
  n"; `target` q = v − 1.
- **Id**: the wire id, "permutation[canonical id]" (§4.5), u(⌈log2(3 + S)⌉) with S woven sites (§4.6).
- **Tag** (§4.5): input = count u32le ‖ lane byte (0, +128 with `caller` 1) ‖ length before the tag u32le ‖ instance
  count u16le ‖ the first min(`tag.coverBytes`, length) bytes; tag = HalfSipHash-1-3(key; input) XOR m_v, with the
  build's two constants.
- **Bytes**, from `wire.py` (whose writer reproduces G3, G4, G4c, G5, G10): header 10 bits, toc 7, id 2, count 1, row
  22 + 40: 82 bits, so **11 B of bits and a 4 B tag, 15 B**, no tail. Identity build, generic id 2, count 0, `target`
  5, `aim` `Vector3.zAxis` (codes 1024, 1024): `00 48 0d 40 00 12 00 00 00 00 00 86 28 ff 78`. With 3-bit woven ids
  (site id 3): `00 48 17 80 00 24 00 00 00 00 00 44 cd e6 70`, still 15 B (83 bits). With ROT's draws the bits are
  `00 48 7d eb cc f4 a2 cf d1 01 00`, tag `31 ab 8a fc` with no mask and `05 b9 d0 a6` under a mask of `5a5a1234`:
  the mask moves only the four tag bytes, as §2.4's "variants differ only in the tag mask" says.
- **Gap.** A6: which frame of a flush carries the ack.

### a5. The server's inbound pipeline (`v5.md` §6.1)

1. **Shape**: a buffer and an optional table; `framesReceived.reliable` + 1.
2. **Budgets**: `inbound.reliable.frames` (60/s, burst 240), then `inbound.reliable.bytes`, charged `buffer.len` 15 +
   8 B × 0 entries. Refused: `inboundFramesExceeded` or `inboundBytesExceeded`, and "a refused reliable frame that its
   header in clear shows tagged advances the expected tag count by one".
3. **Tag**: tagged (extended `rcv` ≥ F_w); candidates e … e + 4, "one hash per candidate count under the player's
   variant mask"; own mask accepts (e ← e + j + 1, `reliableFramesMissing` for j ≥ 1); another variant's mask is
   remembered, giving `tagVariantMismatch` if nothing accepts, else `tagMismatch`; 8 in a row with none accepted is
   `tagMismatchesExceeded` and a `REKEY`. Accepted: the accepted-frame count (the frame key) + 1.
4. **Decode**: allowance = the `inbound.decodeUnits` bucket's whole units; the run's count 1 × 24 is subtracted
   before allocation (`inboundDecodeUnitsExceeded` past it); "Ids go through the permutation; a woven site's id is
   mapped to its definition here"; offsets inverted after rule 2's w < n; rule 6 refuses a non-canonical `aim` code.
   `elementsReceived` + 1, `decodeUnitsReceived` + 24. A raise inside: `decoderRaised`. An ack in this frame naming an
   unsent seq: `ackSeqUnknown`.
5. **Lync's rules and report-only checks**: no control row, answer, enum or instance; reachability: `strike` is
   referenced and (A8) not closed, so neither `unreferencedMessageReceived` nor `genericIdMessageReceived`; no `limit`,
   no trap; report-only: with `fighters` decoys, `decoyKeyReceived` when `target` is in the sender's decoy history
   (A3). With the `caller` bit set: `clientCallSourceUnknown` (recorded for the accepted frame, `v5-integrity.md` §4).
6. **Developer's rules** (`v5-checks.md` §1.4): `derive` runs `fn` in a runner (§1.7); r is "compared as returned"
   for `t.int`; k = |q_v − q_r| against K (A4; A11 for a fractional r); a failure records `deriveMismatch` (evidence

   `derive` commits nothing. The claim requirement ran earlier: `connect` was accepted because `target`'s handle

6b. **Telemetry**: none declared.
7. **Delivery** in a pooled thread; `messagesReceived` and `bytesReceived` + 1 (A10); with no `connect`,

### Findings in (a)

**A1. A later namespace's `HELLO` in the mask window can't be sent as specified — major.**
- *Case.* Variants on. Namespace `arena`'s `WELCOME` arrives (F_w = 1); the mask's `ScreenGui` hasn't replicated yet
  (its arrival after `WELCOME` is unmeasured, `v5.md` §10). Game code now requires a second namespace's view (a lazily
  loaded `shop`, or a staged namespace at its release). By `v5.md` §4.5 the next reliable frame has extended `rcv` ≥
  F_w, so it is not an untagged frame ("a reliable frame is untagged exactly when no `WELCOME` has been sent or its
  extended `rcv` is below F_w … Every other frame is tagged"), and "A client holding no mask yet tags nothing; its
  tagged frames wait". But §4.6 and §5.3 say the `HELLO` "still comes from the shared client shard at once" and
  "`HELLO` never waits for the mask", and `v5-integrity.md` §2.4 "it never waits for the variant".
- *Why it matters.* An implementer who sends it untagged gets the frame refused by rule 7, and the `HELLO` is never
  resent ("a client view sends one `HELLO` per namespace per connection", §5.3), so `shop` never opens for the
  session; one who holds it delays `shop` by the variant's arrival, which §5.3's join-time formula says can't happen.
- *Fix.* State the second: §5.3 "`HELLO` never waits for the mask before the connection's first `WELCOME`; a `HELLO`
  sent after it rides a tagged frame, so it waits with the other tagged frames until the mask is installed", and the
  same in §4.6 and `v5-integrity.md` §2.4's Join bullet.

**A2. Held sends can't be "encoded at fire" before the `WELCOME` — major.**
- *Case.* `v5.md` §5.3: "Each held send is encoded at fire as a run of its own: its id, count − 1 = 0, … and its
  single-row encoding", and "Held sends stay encoded bytes in every case: variants differ only in the tag mask". A
  run's id is the wire id, "permutation[canonical id]", and the permutation's space keys come from the permutation
  nonce in the first `WELCOME` (§4.5), which a pre-`WELCOME` send doesn't have. On the runtime path with `layout.vary`
  (the default), field order and offsets come from the layout seed, "the 64-bit output of HalfSipHash-2-4 under a
  zero key over (permutation nonce ‖ `layout`)" (§4.5), so the row's bits are unknown at fire too.
- *Why it matters.* The rule as written can't be built; the charge it protects is still exact, since no width depends
  on the permutation, the order or the offsets.
- *Fix.* §5.3 Charge: "Each held send is charged at fire the bits of a run of its own (its id, count − 1 = 0, its
  instance count, its single-row encoding), which no layout, permutation or offset changes; it is held as its
  canonical encoding and written at release under the connection's permutation and layout." `v5-integrity.md` §2.4:
  "Held sends are charged at send; the tag, the ids and (on the runtime path) the layout are applied at release."

**A3. Which messages raise `decoyKeyReceived`: three texts, three answers — major.**
- *Case.* A `strike′` naming a key in the sender's decoy history, dropped by its `derive` check (`policy = "drop"`). `v5.md`
  §6.1 lists `decoyKeyReceived` among step 5's report-only checks, which "see every message that passed `limit` and
  isn't a trap's, including those step 6 then drops": a fact. `v5.md` §3.5: "Checks commit and `refers` reports on
  accepted messages": no fact (not accepted). `v5-integrity.md` §8 "A delivered message whose referenced key is in the
  sender's decoy history is `decoyKeyReceived`", §10's trigger "a delivered message …": no fact. For a `strike′` with
  no `connect`, the first two give a fact and the third doesn't.
- *Why it matters.* The fact's known causes and its count differ by reading; the two-sided world's test "each fact
  fires on exactly its trigger" (`v5.md` §9) can't be written.
- *Fix.* Keep §6.1's placement (the one the step list builds) and make the other two say it: `v5.md` §3.5 "Checks
  commit on accepted messages; `refers` reports in step 5, on every message past `limit`"; `v5-integrity.md` §8 and
  §10: "a message past `limit` (`v5.md` §6.1 step 5) whose referenced key …".

**A4. `derive`'s integer tolerance has two readings — major.**
- *Case.* `v5-checks.md` §5.1: "`tolerance` is converted once, at declaration, to an integer K …: ⌊tolerance/step⌋ for
  `t.number` (1 for `t.int`)". Reading one: step is 1 for `t.int`, K = ⌊0/1⌋ = 0, only the derived target passes.
  Reading two: K is 1 for `t.int`, so with `tolerance = 0` a `target` one id away from the derived one passes a
  `"drop"` check.
- *Fix.* "⌊tolerance/step⌋ for `t.number`, ⌊tolerance⌋ for `t.int(min, max)` (step 1)".

**A5. The example game can't show the case the design is about — minor.** As set out above: no reliable claim event,
and the checks file's `strike` (with `origin`) is not the core's. Fix: give `v5.md` §3.4's `strike` the `origin` field
of `v5-checks.md` §7.3 (`origin = t.vector3(-2048, 2048, 1 / 32):claim()`), so every file's example names a field the
core declares.

**A6. Which frame of a flush carries the ack — minor.** `v5.md` §4.1: "Within a flush the client sends its reliable
frame first, then its unreliable frames. The first of them carries an ack". "Them" reads as the unreliable frames or
as all of them; `v5-collections.md` §12.3 says "only the first frame of a flush carries a full ack", the second
reading. For `strike′` it decides whether its own frame carries `'1' seq received`, hence `ackExact`. Fix: "The
flush's first frame, its reliable frame when it has one, carries an ack …".

**A7. Woven sites' client-side rules are unstated — minor.** `v5-tooling.md` §5.3 fixes a woven site's bytes and its
error positions. It doesn't say whether an inline (W2) site runs the caller probe (`v5-integrity.md` §4: "Each client

`limit = { perSecond = 5, burst = 5 }`). Fix, `v5-tooling.md` §5.3: "A woven site's fragment encodes only; it hands
its run to the shard's send path, which applies the probe, `limit`, the join hold and the variant as for `fire`."

**A8. `asDecoded` keeps every claim definition open — minor.** `v5-tooling.md` §5.4: a definition is closed only when
"every occurrence of its name in the client scan set … is part of a woven site that passed the gate … or of an alias
declaration whose uses are all such sites". `v5.md` §3.5's recommended `Net.strike:asDecoded(…)` is such an occurrence
and is no site, so `strike` (and every claim definition using it) stays open and `genericIdMessageReceived` can't

**A9. `limit.slackSeconds` is a schema value outside the hash — minor.** As in a1. It is server-only (§5.4), so not
hashing it is harmless, but §3.4's sentence is then false. Fix, §3.4: "Every value in the schema except

**A10. Per-definition byte counters have no attribution rule — minor.** `bytesSent` and `bytesReceived` are counted
"per definition" at "encode; §6.1 step 7" (`v5.md` §7.4), but messages are bit-packed into shared frames with
headers, tocs, alignment and tags. Fix, §7.4: "a message's bytes are its run's bits over 8 (its share of a shared
run's bits), plus its tail bytes; framing is counted only in the lane's frame counters."

**A11. A fractional `derive` result for `t.int` is undefined — minor.** `v5-checks.md` §1.7 turns a result "outside
the check's domain" into a throw, listing the wrong type, non-finite values and a zero direction; a fraction for a
`t.int` field gives q_r = r − min non-integral, and "the comparison is integer". Fix, §1.7: add "a fraction for a
`t.int` field".

**A12. `v5-checks.md` §1.4's step 5 also reorders reachability — minor.** Beyond the excluded trap item, the same list

resolution before reachability. Fix with the trap item: copy `v5.md` §6.1 step 5's list verbatim.

## 2(b). The reply, and a collection update through encode-once, decode, interpolation and `rewind`

### Setup

The handler of a(5) patches the struck fighter, `Net.fighters:patch(target, { health = 90 })`; the reply traced is
`buy`'s, the design's one reply. `fighters` is the §3.4 collection with `acked = true` (shared schema, hashed), and
two class modifiers, `health = t.int(0, 100):team()` and `title = t.optional(t.string(16)):owner()`; the server view
declares `interest({ position = "position", radius = 128 })`, `team(fn, { onError = "exclude" })`, `owner(fn, {
onError = "exclude" })`, `decoys(behavior, { maxPerViewer = 1, maxSlots = 8 })` and `rewind({})`.

### b1. The reply

`v5.md` §5.2: "an answer row is `slot:u4 epoch:u1 outcome:u2 [reply]`, outcome 0 value, 1 `rejected`, 2
`unanswered`, 3 `limited`"; request and answer runs are single rows; downstream chunks start on a byte boundary
(§4.1). `wire.py` rebuilds G3 from that text (tick `'0'`, toc 9 bits, align, id u1 = 1, count, slot 0, epoch 0,
outcome 0, `reply` u17 of 250): `4a 03 03 f4 01 00`, equal to the golden vector. The client's `invoke` returns
`{ ok = true, value = 250 }`; `ServerResult`'s timing fields exist only on server `invoke` (§3.5). No finding.

### b2. The update, encode-once

- **Units** (`v5-collections.md` §3): "a *cell* chunk, under interest: the records filed in one cell, per partition";
  "a *team* chunk: one (partition or cell, team) pair's `:team()` and fallback `:gated()` fields"; "a *piece*: …
  `:owner()` fields". `health` is a `:team()` field, so its update goes in the (cell, team) chunk of the record's
  filed cell, encoded once and copied to every team member whose block covers that cell (§9's table).
- **Grammar** (§3): `state chunk := collection:u(wc) kind:u1 body`, kind 0 `adds updates`, an update `slot:u(ws) mask
  fields`, "mask: 1 bit per reliable field"; a class field "is coded as `t.optional` of its codec" (§9). At the
  identity build, slot 5, ws = 6 (`maxRecords` 64), wc = 1, reliable fields in name order `health`, `name`, `team`,
  `title`, `wire.py` gives the frame `a4 03 54 11 5a` for a plain field and `a4 03 54 11 b5` for the team chunk (the
  presence bit added): 10 bits of header and toc, aligned, then 1 + 1 + 1 + 3 + 6 + 4 + 1 + 7 bits.
- **Order** (§3): "the viewer's own chunk, then shared partition or cell chunks, then team chunks, then its piece
  chunk"; state chunks before runs and removes in the reliable frame (`v5.md` §4.1), so an `announce` fired after the
  patch sees it.
- **Decoy** (§8.6): "A viewer's copy of a changed shared chunk (partition or cell) is re-encoded, with its decoys'
  rows mixed in, only in a flush where its decoys have adds or updates in that chunk"; that frame leaves
  `FireAllClients` (`v5.md` §4.2). The behaviour runs by the callback rule; a refused decoy is reported natively
  (N1). **Gap:** B2, a decoy's `:team()` field.
- **Class on an optional field.** **Gap:** B3.

### b3. Downstream frames

- **State frame** (`v5.md` §4.1): `'1' seq:u12 tick:u8 in`, `in` "on every state frame" (1 bit, 13 once a stream
  index was received); `toc (down, state) := segs(rows)`.
- **`acked` rows** (`v5-collections.md` §5.1): the acked rows chunk "takes the rows chunk's place … one column block
  per frame"; baselines are the pair's acked ticks within H = 32; nb ∈ {0, 1, 3}; `gen`, `seg` only for nb = 0; rows
  admitted by §7's order under an exact bound. The decoy's rows are predicted from its own slot's history, "which
  holds the values its viewer was sent".
- **Budget** (§7): rows up to `state.bytesPerSecond` × Δt − charged bytes; `weight` absent, so one FIFO per
  collection.

### b4. Client decode and interpolation

- **Decode** (`v5.md` §4.8): the same rules, the allowance 2^22 elements; a refusal counts `framesMalformed` and
  enters `REPORT`. Row acceptance (`v5-collections.md` §2): "applies when the slot is occupied, r = g, T ≥ A and q is
  newer than s". For an acked row with nb ≥ 1, `gen` and `seg` are b0's (§5.1). The client acks only state frames it
  decoded and accepted.
- **Interpolation** (§11): D starts at D₀ = 25 units (0.1 s at 20 Hz) from the first `WELCOME`, then moves one unit a
  second toward max(2/`stateRate`, `minDelaySeconds`) + `jitterFraction` × jitter, sent in `RATE`; τ follows τ* =
  T_n + (c − a_n) × `stateRate` − D × `stateRate` with the ±4% slew; samples are every received row of the occupant.
- **Class fields** decode as nil outside the class; `changed` fires once per frame (§2).

### b5. `rewind`

- **Inputs** (`v5-collections.md` §12.3): for `strike′`, a reliable frame, H is its extended `rcv` (exact unless 256 or
  more reliable frames were sent since the lane's previous receipt); s is the frame's ack or "the newest ack held";
  Q = T_s + held × `stateRate`; P = Q − D × `stateRate`, D "the collection's `interpolationDelaySeconds` option, else
  D_rate". **Gap:** B1, D_rate before any `RATE`.
- **Result** (§12.5): `rewound(perception, key)` returns `position` and `look` at P from the truth ring, "received"
  mode over the viewer's acked samples (the per-pair bits are "set when an acked state frame carried that tick's
  row"), `fromTick`/`toTick`, or `"tickOutOfRange"`, `"ackMissing"`, `"recordMissing"`, `"keyUnknown"`. A decoy of
  the striker resolves from its own ring (§12.6); another viewer's is `"keyUnknown"`. A `rewind` `fields` entry with a
  class is `fieldCodecUnsupported` (§12.2), so neither `health` nor `title` can be rewound.
- **Raised**: no fact (§12.1); `decoyInteractionReported` only through `reportInteraction`.

### Findings in (b)

**B1. D_rate is undefined until the first `RATE` — minor.**
- *Case.* `v5-collections.md` §12.3: "D_rate, the D of the newest `RATE` among frames ≤ H". D₀ travels in the first
  `WELCOME`, not in a `RATE` (`v5.md` §4.6; §11.1: "sent in the connection's first `WELCOME`"). A player whose target
  equals D₀ (jitter 0, or `jitterFraction` 0, the documented way to give "every player the fixed minimum") never gets
  a `RATE`, so every `rewound` for them has no D, and `Lync.perception`'s `interpolationDelaySeconds` has no value.
- *Fix.* "D_rate, the D of the newest `RATE` among frames ≤ H, else the connection's first `WELCOME`'s `delay`."

**B2. A decoy's `:team()` field has no unit to travel in — minor.**
- *Case.* `v5-collections.md` §9: "Bindings and gates run on decoy records as on real ones, so a decoy's class fields
  reach its viewer exactly as a real record's would." A decoy is held by one viewer (§2: "Each viewer's decoys hold
  their own slots"). Its `health`, a `:team()` field, belongs in a (cell, team) chunk, which is shared by every team
  member holding the cell; §8.6 re-encodes only "a viewer's copy of a changed shared chunk (partition or cell)". Either
  the shared team chunk names a slot only one member holds, or the field isn't sent: the text picks neither.
- *Fix.* §8.6: "… of a changed shared chunk (partition, cell or team) …", and §9's Decoys bullet: "a decoy's `:team()`
  and `:gated()` fields ride its viewer's re-encoded team chunk."

**B3. A class modifier on a `t.optional` field gives an optional inside an optional — minor.**
- *Case.* `title = t.optional(t.string(16)):owner()` passes §9's placement ("a top-level reliable field of a
  collection record … one per field") and is "coded as `t.optional` of its codec": presence, presence, string. A
  holder in the class whose `title` is nil receives `'1' '0'`, one outside it `'0'`; both decode to the one Luau
  value nil, so the client can't tell them apart. `v5.md` §3.3 refuses exactly this shape for codecs (`optionalMisplaced`: "each
  would give a second encoding of one value").
- *Fix.* §9 Wire (and `v5.md` §3.3's modifier row): "A class field is coded as `t.optional` of its codec, except that
  a field whose codec is already `t.optional(c)` keeps that one presence bit: 0 is hidden or nil, which its client
  type `T?` already merges."

## 2(c). An input stream index through resend, playout and checks

### Setup

The §3.4 game declares no stream; the trace adds `v5-collections.md` §15's form to `arena`:

### c1. Declaration

  instance or custom codec), else `streamCodecUnsupported`; "a namespace's streams together fit 960 B at 33 copies
  each" (`streamBytesExceeded`): a copy is at most 1 + (1 + 22) + (1 + 54) = 79 bits, 33 of them about 326 B

- `:claim()` is allowed in stream `data` (`v5.md` §3.3, `v5-checks.md` §7.1); `maxRate` on `position`'s handle
  verifies it, so `connect` doesn't throw `claimUnverified` (`v5-collections.md` §15.4); `connect` would throw
  `playoutDepthMissing` without the `playout` call.

### c2. `DEPTH`

`v5-collections.md` §15.2: "Each change of a player's depth sends that client `DEPTH` (control type 4: definition id
u(w), depth u5), which sets the client's resend window"; `v5.md` §4.6's row: "a stream's definition id u(w) of the up
space, depth u5". **Gaps:** C1 (blocking), C2 (major).

### c3. Client: sampling and resend

- "A stream starts at the client's first `set` after its namespace's `WELCOME`" (§15.6); "every index i in (k_last,
  K] takes the latched value", K = ⌊(`GetServerTimeNow()` − epoch) × `stateRate`⌋ (§15.1, §15.3).
- Window: indices [start, K], start = max(a + 1, d), a the newest index the server stated received (`in`), d the
  oldest index whose tick began at most J / `stateRate` + 1/60 s ago: at most J + 2 = 4 copies at J = 2 (§15.3).
- `ref = 1` "when the client holds an acked index a with K − a ≤ 63, back = first − 1 − a".
- Every frame holding a stream chunk "carries `'1' seq received` whenever any state frame has arrived" (§15.3,
  `v5.md` §4.1). **Gaps:** C3 (the mask window), C4 ("perception is exact").

### c4. Encode

`stream chunk := id:u(w) count−1:EG0 first:u12 rp:u1 ref:u1 [back:EG0] copies`; `copy(i) := '1' (same as index i−1) |
'0' { changed:u1 [field single-row encoding] } per top-level field` (§15.3, `v5.md` §4.1). `wire.py` builds one: seq
7, a full ack, three indices from 100 with `ref` 1 and `back` 0, the first copy changing both fields, the second equal
to it, the third changing `position` only: header 43 bits, toc 7, chunk header 20, copies 79 + 1 + 57: **207 bits, 26
B, 30 B with the tag** (`07 20 03 fc ff 93 6a 32 b0 00 04 60 00 80 00 00 02 00 28 09 00 22 00 88 00 20 21 b2 b3 26`
at the G4 key, no mask). It rides "the flush's first unreliable frame"; with variants its tag is XORed with m_v like
every frame's.

### c5. Server: receipt

- `v5.md` §6.1 steps 1–3 on the unreliable lane: frame and byte buckets; tag at x − 4,096, x, x + 4,096 under the
  mask; the replay window (`unreliableSeqDuplicate`, `unreliableSeqOutOfRange`).

### Findings in (c)

**C1. `DEPTH` doesn't say which namespace's stream it names — blocking.**
- *Case.* Control messages travel in namespace 0's chunks (`v5.md` §4.6). `WELCOME` names its namespace ("namespace
  index EG0"); `DEPTH`'s fields are only "a stream's definition id u(w) of the up space, depth u5". Up spaces are per
  namespace ("Each namespace has three"), and w = ⌈log2 count⌉ differs between them. A client holding `arena`
  (4 up ids, w = 2) and `race` (9 up ids, w = 4), both with streams, receives a `DEPTH` row and can't read it: the
  width of its first field, and which stream it sets, are both unknown. Rule 3's "a `DEPTH` id that is not a
  stream's" has no space to look the id up in.
- *Why it matters.* A field width the decoder can't determine is a frame it can't parse; the row is in every frame
  that changes a depth.
- *Fix.* `v5.md` §4.6 and §4.9, `v5-collections.md` §15.2 and §15.7: "4 `DEPTH` | down | namespace index EG0; the
  stream's wire id u(w) of that namespace's up space; depth u5", with rule 3 refusing an index not welcomed or an id
  that is not a stream's there. No golden vector carries `DEPTH` (`v5-3.6-open-streams.md`: none is a stream frame),
  so none changes.

**C2. No `DEPTH` reaches a player who joins after `playout` — major.**
- *Case.* `Net.move:playout({ depthTicks = 2 })` runs at server start, before any player exists. §15.2 sends `DEPTH`
  only on "each change of a player's depth"; a joiner's depth is the all-player value and never changes, so its
  client never learns J. The client's window needs J ("d is the oldest index whose tick began at most J /
  `stateRate` + 1/60 s ago", §15.3), and no default J is stated.
- *Why it matters.* Every player of the common setup has an undefined resend window: an implementation that sends
  only the newest index loses 4.949% of inputs against 0.059% (§15.3's measurement at J = 1 and 5% loss), and one
  that sends the protocol's maximum of 33 copies sends about 8× the J + 2 = 4 copies J = 2 calls for.
- *Fix.* §15.2: "The server sends `DEPTH` to a player in the frame after its namespace's `WELCOME` when a depth is set
  for it, and on each change after; until a client has a `DEPTH` for a stream it sends that stream's newest index
  alone."

**C3. Stream sends in the mask window are unspecified — minor.** With variants, `v5-integrity.md` §2.4 drops "an
unreliable send after `WELCOME` but before the variant" as `unreliableHoldUnsupported`, `waitingFor` 2. A stream
"starts at the client's first `set` after its namespace's `WELCOME`" (§15.6), so between `WELCOME` and the mask each
flush step's chunk is such a send: the text gives either up to 60 local facts a second for as long as the variant
takes (`variantMissing` only after 10 s), or nothing, if sampling counts as not sending. Fix, §15.6: "… after its
namespace's `WELCOME` and, with variants, the mask; indices before that are not sampled, and no fact is raised."

**C4. "Each index's perception is exact" overstates — minor.** `v5-collections.md` §15.3: stream frames carry a full
ack "so each index's perception is exact". The perception also has the reliable horizon H, and a stream frame carries
no receipt (`receipt` `'1'` only "when the frame holds an `ackEveryFrame` message"; `'1'` on any other frame is rule
7), so H is estimated and `receivedExact` false (§12.3); R and the membership used by `rewound` can come from frames
the client hadn't decoded during a reliable stall (§12.9). Fix: "so each index's `ackExact` is true; its reliable
horizon is estimated (`receivedExact` false) unless an `ackEveryFrame` message shares the frame."

**C5. `v5.md` §4.8 charges a stream chunk's whole count — minor.** Rule 10: "The decoder subtracts each run, array and
map count × that element kind's weight w before it allocates", and the grammar calls a stream chunk "a stream's run
chunk" (§4.1). Read literally, a chunk of 33 copies with one new index is charged 33 × 27 units; §7.5 and
`v5-collections.md` §15.4, §15.7 charge only new indices, and charging copies "would refuse an unmodified 60 Hz
stream's frames". Fix, §4.8: "each run count (for a stream chunk, its new indices, `v5-collections.md` §15.4), array
and map count × …".

**C6. `first` and `ref` across a `state.ticksPerSecond` change — minor.** §15.6: "`rp` names which (rate, epoch) a
chunk's indices use, and the server keeps the current and previous pair". §15.4 extends `first` against "T_now the
server's state tick at decode", the new rate's tick, and §15.3's `ref` names "an acked index a" without saying which
pair's index space it is in. A chunk with `rp` naming the previous pair, sent in the round trip after a `RATE`, is
extended against the wrong tick, and a `ref` from a new-rate index to an old-rate a compares codes of two index
spaces. Fix: §15.4 "`first` is extended against the state tick of the pair `rp` names"; §15.3 "`ref` = 1 only against
an index of the same pair".

**C7. Two clocks in the playout offset, and t is not "exact" — minor.**
- `v5-collections.md` §15.4: "s_i = arrival − θ_i, θ_i = epoch + i / `stateRate` on the server's clock". The epoch is
  a `GetServerTimeNow()` instant (`v5.md` §4.1, §4.6) and arrivals are server `os.clock()` (§7.3: "`os.clock()`, for
  every duration Lync measures on the server … no duration is a difference of two clocks"). o absorbs a constant
  offset between the two, not a rate difference, which `GetServerTimeNow()` has up to its 0.6% bound
  (`v5-collections.md` §11.1) while `os.clock()` "is not adjusted by NTP" (`v5-integrity.md` §6). Fix: "θ_i = θ_0 + i / `stateRate` in server `os.clock()`, θ_0 the `os.clock()` reading at the
  epoch, taken once per (rate, epoch) pair".
- `v5-checks.md` §6.2: "t its playout time … so … t advances by exactly 1 / `state.ticksPerSecond` per index", while
  §6.2 also defines t as "`os.clock()` at evaluation" and playout runs "at each server `PostSimulation`" (§15.4): at
  20 Hz and a 60 Hz server, successive indices are evaluated 33.3, 50 or 66.7 ms apart. Fix, §6.2: "on a stream, t is
  the index's due time, θ_i + o + J / `stateRate` (its arrival when it arrived late)", which is exact.

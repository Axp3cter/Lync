## 1. Cross-cutting

### 1.1 One judging rule, applied two ways: one-time universal counters reject generated traps but admit R18, R1 and the identity probe — major

- **Location.** §1: "Each is judged by the recurring work it imposes on a modified client … 'a universal counter
  exists' are not reasons on their own: Lync varies what a counter depends on per build (§2), per server
  (permutation), per session (the key) and per player (§2.4)". §3 decision: "a driver that browses the namespace
  skips them after a one-time change to the tool: no recurring work, which is what §1 asks a measure to impose".
  §5: "one spoof of the two that returns the originals' values passes kinds 1, 2 and 4 in every Lync game and every
  build"; §5 injected frames: "It doesn't see injection fired from a thread of its own".
- **Case.** Three measures with one universal, one-time counter, each identical in every Lync game and build:
  `setthreadidentity(2)` before calling `fire` (§4 identity), `task.defer(listener, frame)` or
  `coroutine.wrap(listener)(frame)` instead of a synchronous `firesignal` (§5 injected frames; the `levels.luau`
  probe shows such a listener sees `debug.info(2, "f")` = nil, as for an engine delivery), and one `hookfunction` of
  `debug.info` and `table.isfrozen` returning the originals' values (§5 self-check). By §3's sentence each imposes
  "no recurring work" and should be rejected; §5 adopts all three. §1's per-build/server/session/player sentence is
  false for all three (and for canaries, whose format is fixed, §8 below).
- **Why it matters.** A reader can't predict an outcome from the rule, and the rule as stated in §1 promises
  per-build work for measures that have none. `v5.md` §6.2 repeats the sentence.
- **Fix.** Write §1's criterion so both decisions follow from it, for example: "A measure is adopted when its fact
  is exact (no cause on an unmodified client, or each cause listed) and its cost is stated; each section states
  'Universal counter: yes, <the counter>' or 'no'. Generated traps are rejected because choosing their names is
  the developer's (brief), not for want of recurring work." Then restrict the per-build sentence to §2's values and
  `v5.md` §4.5's key and permutation, as `reviews/v5-3.6-scope.md` A2 asks, and add the universal-counter line to
  §4, §5 and §9.

### 1.2 The scope audit landed after the revision, and five of its findings stand unapplied in this file — major

- **Location.** Change record: "awaiting: the scope audit `reviews/v5-3.6-scope.md` (not landed)". The audit
  (dated the same day, written after the file) rules on this file in A2, B2, C1, D2 and E1.
- **Case, item by item, as the file reads now:**
  - A2: §1's sentence (1.1 above).
  - B2: `check.reachability` default `true` (§3 option row), with no derivation. Concrete: Roblox games commonly
    keep `Tool`s in `ServerStorage` and clone them into a `Backpack`; a `ModuleScript` inside such a tool that fires
    `Net.x` is outside the client scan set (only `LocalScript`s and client-`RunContext` scripts are scanned
    "wherever stored"), so every unmodified client using the tool produces `unreachable` `basis` 0 by default.
    §10 lists the cause; the default still fires it in every game that has the pattern.
  - C1: `callerProbe.noOuterFrame = "unlisted"` merges "no frame outside Lync" with "source not listed" into one
    bit with one evidence shape (§4, §10 `reportedSourceUnlisted`).
  - D2: canary text is Lync's fixed format (§9; also 8.4 below).
  - E1: §6 rule 4 "positive is a fast client clock, negative a slow one" states one cause as the quantity; §6's
    own `clockRate` causes include a queue draining (`slope` > 0) on an unmodified client.
- **Why it matters.** The brief says to apply the audit when it lands; until it is, this file and the audit
  specify different behaviour for four defaults and one guarantee.
- **Fix.** Apply A2, B2, C1, D2 and E1 as the audit splits them, and record each by id in the change record. For
  B2, at least label the default (derived or chosen, with what would change it) and name the `ServerStorage` tool
  pattern in the option row, not only in §10.

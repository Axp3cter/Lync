## 1. The convention

### 1.1 What the current names get wrong, in one list

The current set uses at least four grammars at once: condition first (`unknownOption`, `missingCallOption`,
`impossibleAck`, `repeatedHello`), subject first (`tagMismatch`, `sendDropped`, `claimUnverified`), a bare noun with
no condition (`intBounds`, `mapKey`, `enumItems`, `constraint`, `releaseTarget`), and a prefix of the reporter
(`reportedIdentity`, `reportedSelfCheck`). Conditions are said many ways for one meaning ("too large", "too many",
"over", "exceeds" for one thing; "error" and "raised" for one thing; "differs", "changed", "mismatch", "stale" for one
thing). Several are metaphors or verdicts (`foreignRemote`, `staleShard`, `earlyAnswer`, `impossibleAck`,
`unsolicitedAnswer`, `canaryEchoed`, `stagedNameLeak`, `solverOff`, which asserts a state the tool cannot read).
One name covers several triggers with different fixes (`sendDropped` has 7, `constraint` 5, `unreachable` 3,
`unresolved` 3). And one meaning has several names (the run-time option codes have four sets across five files).

### 1.2 Rules

**C1. Case.** Every code, counter, evidence field, result field, option key segment and API member is
lowerCamelCase; a type is PascalCase; wire message types stay UPPER (`HELLO`). Abbreviations are written as words
the way Roblox writes them (`buildId`, `UserId`): no `Ref`, `param`, `rtt`, `hMax`, `IsInt`. Words in identifiers
are spelled as Roblox spells them, which is American (`StreamOutBehavior`, `Color3`): `decoyBehaviorRaised`; prose
keeps its own spelling. (Added by the open-naming unit, 2026-10-15.)
- *Why.* `diagnostics.md` §2 already fixed one lowerCamelCase identifier per code, used as the fact's discriminant,
  the result's `error`, the LSP `code` and the docs slug; Luau's own library members (`task.spawn`, `table.freeze`)
  and roblox-ts are lowerCamelCase. Roblox's PascalCase is for engine members and `Enum` items, which are a
  different namespace a game developer never confuses with a string.

**C2. Word order: subject, then condition.** A code is `<subject><Condition>`: the subject is the noun the trigger
is about, in the words the developer already sees (an option name, an API noun, a codec, an artefact); the condition
is exactly one word (or one fixed phrase) from the vocabulary in C3, and it is always last.
- *Why, prior art* (each checked): Roblox writes results this way, `Enum.TeleportResult.GameNotFound`, `GameFull`,
  `GameEnded`; `Enum.ConnectionError.SecurityKeyMismatch`, `DisconnectProtocolMismatch`; `Enum.HttpError.TimedOut`
  (`api`, Roblox 0.741.19 dump). gRPC's compound codes are subject first: `DEADLINE_EXCEEDED`, `RESOURCE_EXHAUSTED`,
  `PERMISSION_DENIED` (`diagnostics.md` §2 cites the code page). Lync's counters already are (`messagesSent`,
  `bytesReceived`), and their OpenTelemetry mapping is subject then verb (`lync.messages.sent`,
  `diagnostics.md` §5.3).
- *Against:* Luau's own lints mix both orders (`UnknownGlobal`, `DuplicateLocal`, but `LocalUnused`,
  `FunctionUnused`, `GlobalUsedAsLocal`; skill reference, `LinterConfig.h` at 0.740), and Node is condition first
  (`ERR_INVALID_ARG_TYPE`). Neither is one grammar, so neither can be copied whole.
- *What subject-first buys that the other order doesn't:* the registry, `lync explain` completion and the docs index
  sort by subject, so every `tag…`, `config…`, `weave…`, `inbound…` code sits together; and the condition is a closed
  suffix set, so the registry test can enforce the grammar by regex (C8), as it already enforces banned words.

**C3. The condition vocabulary.** Each word has one meaning, and no other word means it.

| Condition | Means exactly | Requirement phrase in the message (§12) |
|---|---|---|
| `Missing` | something required is absent when it is needed | `must have <thing>, got none` |
| `Unknown` | a given name, key, id, path or seq names nothing defined where it is looked up | `has no <noun> <value>; <nouns> are <list>` |
| `Duplicate` | a second instance of something that must be unique, or a second call that may be made once | `must be unique, got a second <thing>` |
| `Mismatch` | two values that must be equal differ; the evidence or message names both | `must equal <expected>, got <found>` |
| `OutOfRange` | a number outside its declared interval, or a fraction where an integer is required | `must be in [a, b], got v` |
| `OutOfOrder` | values that must be ordered are not | `must have a <= b, got …` |
| `WrongType` | a Luau value whose type is not the one the position takes | `must be a <type>, got <typeof>` |
| `Unsupported` | a codec, form or kind that is valid elsewhere but that this operation doesn't take | `must be one of <kinds>, got <kind>` |
| `Misplaced` | a marker, option, call or path at a position (kind, direction, lane, side, scope, container) its rule excludes | `must be on <allowed>, got <position>` |
| `Exceeded` | a counted or measured quantity went past its maximum (fixed or configured); the subject names the quantity | `must be at most <max> <unit>, got <n>` |
| `Malformed` | bytes or text that break a format's grammar (a §4.8 rule, TOML syntax, the PVS table format) | callers: `must be <format>, got <first rule broken>`; facts and build: none |
| `Refused` | a value game code gave that a declared Lync rule (a codec's encode rule, a canary's no-write rule) rejects | `must <rule>, got <value>` |
| `Unresolved` | an arrived reference that can't be bound to a live object on this peer | (facts only) |
| `Unmatched` | an arrival that must pair with an earlier item finds none | (facts and counters) |
| `Unverified` | a claim leaf with no verifier declared | `must have a validator or a check, got none` |
| `Raised` | a function threw | `<function> raised` + the game's own text |
| `Yielded` | a function yielded where it must run to completion | `<function> yielded` |
| `Below<Bound>`, `Before<Event>` | a measured time below a bound, or before an event, both named in the word | (facts only) |
| `Received` | an arrival that is itself the observation (a trap's message, a decoy's key, a canary value) | (facts only) |
| `Reported` | game code stated it through a Lync call (one use: `decoyInteractionReported`) | (facts only) |
| `Found` | a build scan found an instance of the subject | `<subject> found at <path>` |
| `Failed` | an external tool or service returned failure (compiler, parser, Open Cloud) | `<tool> failed: <its text>` |
| `Shadowed` | a local hides a name the weave needs (Luau's own term, lint `LocalShadow`) | build only |
| `Indivisible`, `Empty`, `Disabled` | one use each: a step that doesn't divide its range; an element of zero bits; a Roblox boolean setting that is false | as the code page states |

**C4. Grammar per kind.**

| Kind | Form | Example |
|---|---|---|
| declaration | `<schema construct><Condition>`; option-table codes start `definitionOption` | `enumItemDuplicate`, `definitionOptionUnknown` |
| caller | `<API noun><Condition>`; option-table codes start `callOption`, one set for every run-time call | `fieldPathUnknown`, `callOptionOutOfRange` |
| fault | `<game function's role><Raised\|Yielded>`; `<binding>Missing` | `validatorRaised`, `ownerBindingMissing` |
| fact, observed by Lync | `<wire or API noun><Condition>` | `inboundBytesExceeded`, `tagMismatch` |
| fact, stated by the client | `client<Subject><Condition>`: the client's own count or bit, marked in the name | `clientIdentityMismatch` |
| outcome | a past participle, or `<subject><Participle>`, saying how the call ended | `timedOut`, `playerLeft` |
| build | `<artefact or construct><Condition>`; scan presence is `Found`, artefact comparison `Mismatch` | `shardDigestMismatch`, `remoteInstanceFound` |
| counter, a count | `<plural items><Participle>` | `messagesSent`, `answersTimedOut` |
| counter, a level | `<subject><Quantity>` | `joinHoldBytes`, `clockSlope` |
| evidence and result field | a noun; a 0/1 flag is `<subject><Condition>` or a participle; a trigger discriminator is `case` | `buildIdMismatch`, `sinceSentSeconds` |
| option | `<group>.<quantity>[<Unit>]` (C5) | `observe.windowSeconds` |
| API | an action is a verb (`fire`); an accessor is a noun (`counters`); a server-view declaration reads as a predicate of its handle (`field("target"):refers(Net.fighters)`); a callback registration has `observe`'s shape | `Lync.telemetry.observeAtoms(fn)` |

`internal` is the one code outside the grammar: it names a family, not a trigger (rustc's internal compiler error,
gRPC `INTERNAL`).

**C5. Numbers and units in names.**
- **Durations end in `Seconds`** and are in seconds, never tenths or milliseconds: `timeoutSeconds`,
  `observe.windowSeconds`, `clock.beaconSeconds` (wire stays u4 tenths). Prior art, fetched 2026-10-15: Kubernetes
  API conventions, "Units must either be explicit in the field name (e.g., `timeoutSeconds`) … we use the
  `fooSeconds` convention for durations"; Prometheus naming, "SHOULD use base units (e.g. seconds, bytes …)" and
  "SHOULD have a suffix describing the unit, in plural form". Roblox writes durations as `RespawnTime` and
  `HoldDuration` with no unit (both checked in the dump); Lync can't rely on that, since its options today mix
  seconds, tenths of a second (`clock.beacon`) and Hz (`state.rate`).
- **Sizes end in `Bytes`**; **rates are `<items>PerSecond`** (`state.bytesPerSecond`, not `state.budget`; never Hz);
  **counts are plural nouns** (`frames`, `elements`, `attempts`).
- **Limits are `max<Quantity>` and thresholds `min<Quantity>`**, Roblox's order (`MaxPlayers`,
  `MaxActivationDistance`, checked): `maxRecords`, `sealed.maxOutstanding`, `clock.minSlope`.
- **Lengths in world space carry no unit**: studs, as Roblox's `StreamingTargetRadius`, `MaxActivationDistance` and
  `WalkSpeed` do (checked): `radius`, `maxDistance`.
- **Fractions end in `Fraction`**, multipliers of a named quantity are `<quantity>Fraction` too
  (`answerTiming.pingFraction`), never a bare `factor`, `floor` or `oneIn`.
- **Instants given to game code end in `Time`** (`GetServerTimeNow()` values: `firstTime`, `deadlineTime`); elapsed
  times are `since<Event>Seconds`; −1 is the one sentinel for "no such moment", stated on each page.
- **An `os.clock()` reading in milliseconds** is `clockMilliseconds` (⌊`os.clock()` × 1000⌋ mod 2^32, a u32 in a
  binary layout that game code reads, where integer milliseconds keep differences exact): the one name in
  milliseconds, and never a duration. (Added by the open-naming unit, 2026-10-15.)

**C6. Booleans** are named for what `true` does, as a verb phrase or a participle, never negated and never a bare
noun: `layout.vary`, `sealed.hideLength`, `weave.foldLiterals`, `printFacts`; not `console`, `profile`,
`weave.literals`, `build.offsets`.

**C7. What names never use.**
- *Metaphors:* `foreign`, `stale`, `early`, `late`, `raw`, `echo`, `leak`, `gap`, `conflict`, `off` (as a state),
  `budget` (for a bucket the option calls `inbound`).
- *Vague condition words:* `error` (as a condition; the code is the error), `invalid`, `bad`, `range` alone,
  `placement` (a noun), `limit` as a condition, `twice`, `differs`, `changed`, `short`, `incomplete`.
- *Verdicts and intent:* `impossible`, `unsolicited`, `suspicious`, plus the registry's banned list (`v5.md` §7.1).
- *Negated nouns:* `notACodec`, `notHeld`, `unparsed`; a name says what was found, not what wasn't.
- *The word `kind`* in evidence: it is the union discriminant of game payloads (`v5.md` §3.3), the draft 2 clash
  `diagnostics.md` §5.1 removed from facts. A discriminator is `case`; the game's own integer is `gameKind`.

**C8. Enforcement.** The registry test of `v5.md` §7.1 gains one check: every code except `internal` matches
`^[a-z][A-Za-z0-9]*(Missing|Unknown|Duplicate|Mismatch|OutOfRange|OutOfOrder|WrongType|Unsupported|Misplaced|Exceeded|Malformed|Refused|Unresolved|Unmatched|Unverified|Raised|Yielded|Below[A-Z][a-z]+|Before[A-Z][a-z]+|Received|Reported|Found|Failed|Shadowed|Indivisible|Empty|Disabled)$`,
outcome codes come from the outcome list, a fact whose evidence is client-stated starts with `client` and no other
does, and every option whose registry unit is s or B ends in `Seconds` or `Bytes`.

## 5. Facts, with their evidence fields

## 12. Messages

**The rule.** The message grammar of `v5.md` §7.1 stays (`source:line: [Lync] <code>: <subject> must <requirement>,
got <value>[; <fix>]`, one line, at most 200 bytes after the position). What this convention adds:
1. **The subject is the code's subject in the user's names**: the code says `callOption`, the line names the
   option (`arena.strike:field("origin"):within option "maxDistanse"`); the code says `shard`, the line names the
   shard's path.
2. **The requirement is the positive form of the code's condition word**, from the third column of C3, and states
   the same requirement the code names; the line never introduces a second word for the condition ("too big" in a
   line whose code says `Exceeded`).
3. **`got` gives the value or state found**, rendered by `show()`; for `Missing` it is `got none`.
4. **A fix only when there is exactly one**, as today.
5. **Facts print constant templates** (`v5.md` §7.4): `[Lync] <code>: {count} in {seconds} s, {players} players,
   {definitions} definitions`; the code is the only part that varies by trigger, which is why splits (§11.2) make
   console lines more useful at no cost in rows: one Error Report row per code.
6. **`Found` build codes** have no requirement: `<what> found: <path>`, then the help line from the code page.
